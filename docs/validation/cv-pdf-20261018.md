# PDF CV reading follow-up

## Confirmed defects and changes

- The previous reader triggered OCR only when the combined text layer contained fewer than 40 characters. A header or a readable first page could therefore hide image-based CV sections or unreadable later pages.
- A local PDF parser failure did not reach the existing OCR fallback.
- DOCX and TXT uploads were still accepted despite the requested PDF-only boundary.
- OCR inherited the shared 25-second provider request timeout. It now has a dedicated 45-second timeout, while the CV page declares a 180-second Server Action budget. Other Gemini features keep their existing timeout.
- A real analysis request returned provider HTTP 503 during verification. CV analysis now retries that temporary response once, just as OCR does. Rate-limit errors remain explicit and are not repeatedly retried.

The reader now checks the actual PDF structure, encryption and page count before any OCR request. Image-containing PDFs are recognized in full even when they also contain substantial text. Text-only extraction checks each page and text readability. A valid PDF that the local parser cannot read also falls back to OCR. File-picker, drag-and-drop, and server checks allow PDF only; successful uploads are stored with a `.pdf` path and `application/pdf` content type. Limits remain 3 MiB, 15 pages and 40,000 extracted characters.

Existing analysis history, including earlier DOCX/TXT records, is retained. Existing pasted-text entry and account-scoped storage are preserved. Consent explains when the full PDF is sent to Gemini. No CV, extracted personal text, API key, or account data was added to the repository or test output.

## Verification

- Unit checks cover native text, image-only PDFs, text plus image on one page, mixed text/image pages, unreadable later pages, local parser failures, encrypted/broken/oversized PDFs, wrong extensions and MIME types, OCR output validation, temporary outages and quota failures.
- Action checks cover the verified owner, normalized PDF upload metadata, no analysis/storage writes after OCR failure, no saved result after analysis failure, cleanup after a database save failure, consent and pasted-text compatibility.
- The full remote browser suite exposed a shared-reader regression: the business editor generates TXT assignments, which had also used the CV reader. Business PDF/DOCX/TXT reading is now a separate module with its own regression checks; the PDF-only policy applies to CV uploads. The business editor and its existing paired-content browser check are retained.
- Three synthetic PDF formats were sent to the real configured Gemini provider: scan, mixed text/image on one page, and multiple text/image pages. All three OCR outputs contained the expected `PostgreSQL` and `Pandas` image content; both mixed cases retained the native `EDUCATION` heading.
- The first combined scan/analysis check encountered provider HTTP 503 after successful OCR. A subsequent check encountered HTTP 429; it was surfaced without saving a result. Separate analysis verification confirmed the configured test key/model had reached its free-tier limit of 20 requests per day. No additional requests, automatic model switch, billing change or fake analysis were used to bypass this external limit. End-to-end live analysis therefore remains unverified for this follow-up until provider quota resets; recovery and save behavior passed deterministic unit checks.
- The previously approved personal CV sample was no longer present at its supplied Downloads path. No other personal CV was substituted or sent externally. Real API verification used synthetic documents without personal/contact data.

Opt-in live checks are in `platform/tests/integration/cv/live-pdf.test.ts`. They are skipped in ordinary CI. Set `R2W_RUN_LIVE_CV=1` only when intentionally using provider quota. The optional `R2W_CV_SAMPLE_FILE` check requires a specifically approved sample and never copies it into the repository.
